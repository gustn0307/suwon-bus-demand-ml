# AI개발 수행내역서 초안

과제명: **수원시 버스 정류장별 일일 승차 수요 예측 및 시각화 서비스**  
작성 기준일: 2026-10-29  
담당자·교육과정·제출일: 제출자가 기입

이 초안은 실제 실행 결과를 바탕으로 작성하였다. 참고 HWP는 본문을 직접 파싱하지 못해 세부 서식은 확인하지 않았다. 사용자 지시문과 읽을 수 있는 보고서 예시의 목차를 따랐으며 HWP 최종 편집은 별도 수행해야 한다.

## Ⅰ. AI개발 수행내용

### 1. 목적 및 현황

공공 버스 승하차 집계에서 정류소별 이용 규모와 날짜별 패턴을 분석하고, 날짜와 정류소를 선택하면 예상 **하루 승차 인원**을 확인하는 시범 서비스를 구축하였다. 일별 집계만 있으므로 시간대별 수요나 개별 버스의 실제 혼잡도는 다루지 않는다.

### 2. 범위

제공된 수원시 2026년 6–8월 관측 129,049행, 1,435개 정류소를 품질 검증하였다. 신속한 MVP 구현을 위해 6–7월 유효 관측일 55일 이상 정류소 중 같은 기간 승차합계 상위 100개를 대상으로 제한하였다. 실제 선택된 정류소는 모두 61일 관측되었다. 8월 데이터는 정류소 선정에 사용하지 않았다. 같은 정류소명이 서로 다른 ID에 붙을 수 있으므로 식별 기준은 ID이다.

DB·API·LLM·로그인·클라우드 배포·발표 자료는 범위에 포함하지 않았다. 원본 CSV를 덮어쓰거나 복제하지 않고 별도 모델·결과 파일만 생성하였다.

### 3. 추진 방법

참고자료 검토 → 원본 스키마·품질 검증 → 대상 선정과 EDA → 시간 분할 → Pipeline 기반 세 후보 비교 → 검증 MAE로 모델 선택 → 6–7월 재학습 → 8월 최종 평가 → Streamlit MVP → 실제 실행 검증 순으로 진행하였다. 참고자료별 실제 접근 범위는 `reference_review.md`에 기록하였다.

기존 학습 산출물에 기록된 Python 버전은 3.12.6이며 pandas 2.3.3, NumPy 2.5.4, Scikit-learn 1.8.0, joblib 1.6.0을 사용하였다. Streamlit 버전은 1.66.1이며 필요한 라이브러리는 프로젝트 `.venv`에 설치하고 `requirements.txt`에 버전을 고정하였다.

학원 PC의 프로젝트 위치는 `D:\kang\workspace\suwon-bus-demand-ml`, 집 PC는 `E:\kang\workspace\suwon-bus-demand-ml`이며 두 환경에서 프로젝트를 실행하였다. 집 PC의 Python은 3.12.10이며 requirements 설치, Streamlit 로컬 실행과 실제 예측 버튼 테스트를 완료하였다. 2026-10-29 집 PC 재검증에서는 기존 모델·노트북·평가 지표·예측 결과를 보존하고 재학습하지 않았다. 공통 실행 안내는 README에 기록하였다.

## Ⅱ. 연구개발 주요 결과물

### 1. 데이터 출처·구조·품질

출처: 제공 자료에 기재된 **경기데이터드림 ‘경기도 정류소 별 승하차 인원 집계’**, 2026년 6–8월 수원시. 본 작업에서는 제공 CSV를 사용했으며 원 사이트 다운로드·수집 이력은 재검증하지 않았다. 최종 제출 시 상세 데이터셋 URL·수집일·이용 조건을 보완해야 한다.

| 항목 | 실제 확인 결과 |
|---|---|
| 기간 | 2026-06-01부터 2026-08-31까지, 92일 |
| 규모 | 129,049행, 9개 컬럼, 정류소ID 1,435개 |
| 관할관청 | 모든 행 수원시 |
| 결측·정류소/날짜 중복·음수 인원 | 모두 0건 |
| 승차합계 0인 실제 관측 | 5,481행 유지 |
| 전체 ID×날짜 조합 중 미관측 | 2,971개, 임의 0 대체 안 함 |

컬럼은 승하차일자·관할관청·정류소ID·정류소번호·정류소명·승차합계·초승·환승·하차이다. 목표 변수는 승차합계이고, 정류소명·번호는 화면 표시용이다. CRLF를 LF로 정규화한 원본 비교용 SHA-256은 기존 기대값 `67eab89c329abbfe75421c9b25e2aec0dadd9dfc699b2096dd2bf0da4ae4811b`와 같다.

집 PC의 CSV는 Git 줄바꿈 변환으로 실제 파일 해시가 달랐다. 2026-10-29 CRLF 129,050개를 메모리에서 LF로 정규화하면 Git 원본과 바이트 전체가 일치함을 확인하였다. 129,049행·9개 컬럼 및 모든 데이터 값·순서도 동일하였다. 검증 코드는 정규화한 해시로 기존 기대값과 비교하며 CSV 파일을 수정하지 않는다. 실제 파일 해시와 정규화 해시는 `outputs/validation.json`에 별도로 기록하였다.

### 3. 전처리 및 누수 방지

ID와 번호는 문자열, 날짜는 datetime으로 변환하였다. 입력은 정류소ID와 날짜만 받고 날짜로부터 요일·주말 여부·월·일을 생성하였다. 당일 결과인 승차합계·초승·환승·하차를 입력에서 차단하였다.

정류소ID와 요일은 OneHotEncoder(handle_unknown='ignore'), 수치형 날짜 특성은 StandardScaler로 변환하였다. 피처 생성→ColumnTransformer→회귀모델을 Pipeline으로 묶어 학습 구간에서만 전처리를 fit하고 같은 규칙으로 예측하였다. 결측·중복이 없어 별도 삭제나 대체는 하지 않았다. 원본 미관측을 0명으로 채우지 않았으며 큰 수요도 임의 제거하지 않았다.

인원 예측이 음수가 되는 것을 막기 위해 평가와 앱에서 모두 0 이상으로 제한한다. 평가는 실수 예측을 그대로 사용하고 화면에서만 반올림한다.

### 4. 모델 정의·선정·평가

| 구분 | 기간 | 행 수 | 역할 |
|---|---|---:|---|
| Train | 2026-06-01부터 2026-06-30까지 | 3,000 | 후보 학습 |
| Validation | 2026-07-01부터 2026-07-31까지 | 3,100 | 7월 MAE로 후보 선택 |
| Final training | 2026-06-01부터 2026-07-31까지 | 6,100 | 확정 후보 재학습 |
| Test | 2026-08-01부터 2026-08-31까지 | 3,100 | 확정 모델 단 한 번 평가 |

DummyRegressor(mean), Ridge(alpha=1.0), RandomForestRegressor를 비교하였다. RF는 60개 트리, 최대 깊이 20, 리프 최소 3, random_state=42, n_jobs=2로 고정하여 시간·메모리와 과적합을 제한하였다. 대용량 GridSearch나 추가 튜닝은 하지 않았다.

| 후보 모델 | 구간 | MAE(명) | RMSE(명) | R² |
|---|---|---:|---:|---:|
| Dummy | Train | 814.095 | 1279.195 | 0.0000 |
| Dummy | Validation | 815.271 | 1225.172 | -0.0065 |
| Ridge | Train | 193.889 | 274.989 | 0.9538 |
| Ridge | Validation | 215.933 | 297.517 | 0.9406 |
| RandomForest | Train | 302.480 | 376.343 | 0.9134 |
| RandomForest | Validation | 329.460 | 398.001 | 0.8938 |

![그림 2. 6월 학습 후보의 Train·Validation 성능](../outputs/figures/model_comparison.png)

7월 MAE가 가장 작은 **Ridge**를 선택하였다. 이는 제한된 설정에서의 결과이며 RF의 모든 설정보다 우수하다는 뜻은 아니다. 지시된 대상 선정에 7월을 사용했으므로 7월 검증은 정류소 집합 선정과 완전히 독립적이지 않다. 8월은 대상 선정과 후보 선택 모두에 사용하지 않았다.

최종 Ridge를 6–7월에 재학습한 결과는 다음과 같다. Final training은 재학습 데이터의 적합도이고 미래 성능이 아니다.

| 최종 Ridge | MAE(명) | RMSE(명) | R² |
|---|---:|---:|---:|
| Final training: 6–7월 | 182.972 | 269.904 | 0.9535 |
| Test: 8월 | **218.860** | **299.136** | **0.9387** |

![그림 3. 8월 실제값 대 예측값 및 대상 정류소 일별 합계](../outputs/figures/test_actual_vs_predicted.png)

테스트 MAE는 한 정류소·하루당 평균 절대 오차 약 219명이라는 뜻이다. R² 0.9387을 정확도 93.87%로 해석하지 않는다. 정류소 간 평균 수요 차이를 설명하는 효과와 개별 날짜 변동 예측 능력을 구분해야 한다. 그림 3에서는 일부 고수요 관측과 여러 날짜의 합계에 과소추정이 남아 있다. 원인은 추가 데이터 없이 입증하지 않았다.

최종 Pipeline은 `models/demand_pipeline.joblib`에 압축 저장했으며 2,909 bytes이다. 지표는 `outputs/metrics.json`, 대상은 `stations.csv`, 최종 예측은 `test_predictions.csv`에 저장하였다. 그림과 표는 같은 테스트 예측을 재사용하며 별도 모델 선택을 하지 않는다.

### 5. Streamlit 화면 및 기능

`app.py`는 다음 실제 기능을 제공한다.

1. 정류소명 + 정류소번호 + 정류소ID로 구분되는 100개 선택지와 날짜 입력.
2. 예측 버튼과 예상 **일일 승차 인원(명)** 표시.
3. 선택 정류소의 6–8월 실제 일별 기록과 요일별 관측 평균 차트.
4. 최종 모델명·8월 MAE·RMSE·R² 및 대상 규모 표시.
5. 학습일 이후 예측에 대해 과거 3개월 자료에 근거한 제한적 추정이며, 실제 모델 학습은 6–7월이고 8월은 테스트라는 안내. 날씨·공휴일·노선 변경 미반영 한계 표시.

실행 명령: `.venv\Scripts\python.exe -m streamlit run app.py`.

**앱 화면 이미지는 아직 첨부하지 않았다.** AppTest와 서버 응답으로 기능을 검증하였고 사용자도 집 PC에서 실제 예측 버튼을 테스트하였다. 최종 제출 전 사용자가 실제 화면을 캡처하여 이 위치에 삽입해야 한다. 위 그림 1–3은 실제로 생성된 분석 그림이다.

### 6. 실제 실행 검증

분석 노트북 12개 셀 중 코드 6개 셀의 저장된 전체 실행 결과와 오류 없음을 확인하였다. 이번 수정에서는 노트북을 재실행하지 않았다. 2026-10-29 집 PC(Python 3.12.10)에서 줄바꿈 검증을 수정한 뒤 `.\.venv\Scripts\python.exe verify.py`를 실행하여 6개 테스트 모두 통과(실패 0, 오류 0)하였다: 원본·관측 보존(LF·CRLF 해시 비교 포함), 8월 변조 시 대상 선정 불변, 결과성 컬럼 변조 시 입력·예측 불변, 저장 모델의 전체 대상 미래 예측·미지 범주 처리, 노트북·시간 분할·선정의 일관성, 앱 import·정류소·날짜 변경·버튼 예측이다.

실제 Streamlit 프로세스의 health `ok`, 루트 페이지 HTTP 200을 확인한 뒤 직접 시작한 서버를 종료하였다. AppTest는 기능 검사이며 실제 브라우저 화면의 시각 검사를 대신했다고 주장하지 않는다. 검증 기록은 `outputs/validation.json`이다. 분석 그림 3개는 생성 후 직접 열어 제목·축·범례와 잘림 여부를 확인하였다.

## Ⅲ. 결론 및 한계

제한된 대상에서 정류소ID·날짜만으로 학습과 예측이 이어지는 로컬 MVP를 완성하였다. 7월 검증으로 선정한 Ridge의 8월 MAE는 218.860명, RMSE는 299.136명, R²는 0.9387이었다. 모든 값은 이번 CSV를 실제 실행한 결과이다. 모델은 6–7월에만 학습하고 8월 테스트를 학습에 재사용하지 않았다.

학습 기간이 두 달로 짧고 대상이 고수요 정류소에 한정되어 전체 수원시·저수요·신규 정류소·다른 계절로 일반화할 수 없다. 날짜만으로 공휴일·기상·방학·행사·노선 변경을 반영할 수 없고, 다른 연도 날짜에도 장기 추세를 학습하지 못한다. 예측구간이나 개별 정류소별 보장 성능은 제공하지 않는다. 후속 연구에는 장기 자료와 외부 요인, 새로운 독립 기간 평가가 필요하나 이번 MVP에는 추가하지 않았다.

제출 전 남은 작업은 HWP 서식에 초안과 실제 그림을 옮기고 인적사항을 기입하는 것, 실제 앱 화면을 캡처하는 것, 원 데이터 상세 출처·수집일·이용 조건을 확인하는 것이다. GitHub 저장소 [gustn0307/suwon-bus-demand-ml](https://github.com/gustn0307/suwon-bus-demand-ml)의 `main` 브랜치에 기존 MVP의 Commit·Push를 완료하였다. 이번 검증 코드·문서 수정은 로컬 변경 상태로 두며 사용자가 SourceTree에서 검토 후 Commit·Push한다.
